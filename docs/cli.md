# CLI contract

| Command | Behavior |
| --- | --- |
| `agent-sightline [repository]` / `scan` | Discover and summarize compatible configuration |
| `explain <target>` | Full load decisions, source lines, effective instructions/settings/extensions |
| `diff <target> --clients codex,claude,copilot` | Instruction content recipients and extensions by client |
| `doctor` | Extension validation; `--probe` opts into local stdio startup |
| `ui` | Loopback browser inspector; `--no-open` prints URL |
| `demo --ui` | Open the bundled sample in the browser, excluding personal configuration |
| `report --format html --output report.html` | Portable, self-contained report |
| `ci --fail-on warn` | JSON diagnostics; finding threshold sets exit 1 |
| `adapters --json` | Rule evidence/version/limitations |
| `version` / `--version` | Package version |

The first terminal summary shows each detected client's unique loaded instruction sources, effective instruction bytes, conditional sources and truncation. Conditional sources await trust, approval or another loading condition. Use `explain` to inspect their source and reason. Repeated source segments share one source count, and exhausted byte budgets retain their truncation count.

Implicit scans select the nearest enclosing Git root while keeping the current directory as the default target and session directory. Relative `explain` and `diff` targets resolve from the current directory. Git worktree `.git` files and nested repositories are recognized. A directory with no Git ancestor uses itself as the inspection boundary. An explicit `--repo` or positional repository selects the boundary and resolves relative targets from that directory. SDK calls with an omitted `ScanOptions.repo` use the same discovery behavior. The browser retains its selected boundary through target changes and reloads.

Common flags: `--repo`, `--session-dir`, `--client` or `--clients`, `--profile` (Codex), `--no-user`, `--home` (isolated synthetic home), `--trust auto|trusted|untrusted`, `--system`, `--json`, `--format terminal|json|html`, `--severity error|warn|info`, `--fail-on error|warn|info|none`, `--output`.

`--session-dir <directory>` selects the agent's starting directory independently of the inspected target. Relative paths resolve from the invocation directory when the repository is inferred, and from the selected repository when `--repo` or a positional repository is supplied. The starting directory must exist inside the inspection boundary, including its symlink destination. Omitting the option uses the target directory. SDK callers pass `ScanOptions.sessionDirectory`. JSON always records the modeled directory in `sessionDirectory` and adds `inputs.sessionDirectory` for an explicit selection.

For example, `agent-sightline explain src/payments/refund.ts --session-dir . --client codex --trust trusted` models Codex launched at the repository root. Its startup AGENTS chain and project configuration follow that starting directory. Claude additionally loads descendant CLAUDE instructions and rules when the target is opened. On-demand discovery excludes AGENTS files and targets outside the starting directory. Copilot startup instructions, workspace MCP sources and root/current-directory rule discovery follow the starting directory while path metadata matches the selected target.

The local inspector shows Starts in beside the target. Its scan-scope dialog accepts a starting directory and provides Use target directory to restore automatic selection. An explicit choice survives target changes, refresh, reload and browser history. Standalone HTML displays the captured directory and selection mode, including after offline re-export. Live URLs use `session` for the selected directory and an empty `session` for automatic mode. A missing parameter uses the server's CLI-configured choice.

Claude on-demand instruction files and rules use a model-specific character limit. Captured `model`, `env.ANTHROPIC_MODEL`, per-class model pins, `modelOverrides`, personal/managed `modelPicker` bindings and context environment settings determine the inspected budget. Known models retain their catalog window unless `DISABLE_COMPACT` permits a `CLAUDE_CODE_MAX_CONTEXT_TOKENS` override. The inspector marks the original source boundary and preserves the selected prefix in offline exports. Optional decision `truncation` metadata records `unit`, `limit`, `line` and `column`. The source position identifies the first omitted character in the original file. Unknown session inputs retain conditional limits.

Relative CODEX_HOME, CLAUDE_CONFIG_DIR, COPILOT_HOME and GEMINI_CLI_HOME values resolve from the modeled native working directory. Empty values use each client's default. Codex on Windows uses the OS profile directory for its default home, independently of HOME or USERPROFILE overrides. A custom CLAUDE_CONFIG_DIR also selects its `.claude.json` state file. An explicit `--home` selects the synthetic home's documented locations.

`--max-entries` sets the repository discovery budget, defaulting to 50,000 filesystem entries. `--max-user-files` sets the matching-file budget for each user instruction, rule, skill or hook root, defaulting to 4,000. Both accept non-negative safe integers. Zero prevents repository-entry processing or matching-file reads for the respective budget. Explicit target-chain files and user settings use their documented direct lookup paths. The file picker shares the repository entry budget.

Reports add optional `discovery` metadata with `complete`, `repositoryEntries`, `repositoryEntryLimit` and `userFileLimit`. Limits and inaccessible locations produce an incomplete-discovery status that survives severity filtering and portable export. The terminal and browser keep that status visible. Use `--severity warn` to inspect the reasons, and `--fail-on warn` when CI should reject partial results.

Syntax, glob and client-field diagnostics follow the selected clients' target discovery decisions. Filename-placement warnings apply to configuration namespaces on the target directory chain. MCP-shape diagnostics use the selected clients’ loading decisions. Discovered sources retain validity metadata and outside-target explanations across client scopes. Selecting another target or project boundary recomputes the relevant findings. Personal state and other explicitly considered sources retain their syntax diagnostics under ignored trust decisions. Filesystem discovery findings and completeness describe the inspected repository and documented user locations.

`--severity` filters displayed findings at or above that level. `--fail-on` always evaluates the unfiltered report. CI defaults to `--json --fail-on error`; other commands default to no threshold. Unknown/missing arguments, invalid targets, bad formats and write errors exit 2. Help/version exit 0. Non-interactive output has no ANSI or animations.

The terminal scan summary groups identical diagnostics across clients at the same source location and shows severity totals for the complete grouped list after severity filtering. It displays up to 12 findings and reports the full count when the list continues. Findings at different files, lines, columns or configuration keys stay separate. Each displayed finding includes its source line and column plus related locations. Use `explain` for all client-specific findings or `--json` for machine-readable records. Experimental clients carry an explicit label in the summary. Empty scans include the bundled demo command.

Browser rescans retain the actual selected target and Codex profile when their displayed report values are redacted. Submitting an unchanged target with Inspect or Enter keeps that target and its starting directory. Applying an unchanged profile keeps the selected file. Clearing the profile field selects the base configuration. Invalid profile names produce a server validation message and preserve the last successful report for export.

Explicit trust assumptions add optional `inputs.trust` metadata with `auto`, `trusted` or `untrusted`. These generated control values retain their enum representation when private source text contains the same words. Source previews, copied instructions and diagnostic prose keep their redaction. The inspector uses this metadata for the trust control and the visible scan-scope details in live and standalone reports. Earlier reports use their captured assumption text.

Live links keep explicitly entered request selections through reload and browser history. An omitted URL parameter uses the server's CLI-configured default. Standalone HTML captures retain their redacted diagnostic values and trust assumption. The request selections used by the local server stay outside those files.

`--profile review` models Codex with `$CODEX_HOME/review.config.toml`. Profile names use letters, numbers, hyphens and underscores. The selected file loads after base user configuration and before applicable project layers. It requires user configuration and Codex among the selected clients. JSON adds optional `inputs.codexProfile`. Omitting the flag loads the base configuration. Legacy `[profiles.*]` definitions and the retired `profile` selector receive migration diagnostics.

SIGINT and SIGTERM interruptions stop active probes before returning exit code 130 or 143 respectively. SDK callers can pass `ScanOptions.signal` to cancel an inspection.

No-argument runs include explicit documented user configuration locations. Use `--no-user` for repository-only CI. Unknown project trust is conditional. `--trust trusted` models a trusted session and, for Claude project MCP, approved servers; it does not change the client’s real trust state.

Gemini auto trust reads its process-environment decision and saved folder-trust file. Pending approval retains current global context and marks the trusted project context as conditional. A saved rejection excludes project settings, context and MCP startup. `--no-user` excludes saved folder decisions, leaving project context conditional unless an environment decision or explicit trust assumption resolves it. `--trust trusted` and `--trust untrusted` select inspection assumptions. Custom `GEMINI_CLI_HOME` and `GEMINI_CLI_TRUSTED_FOLDERS_PATH` are supported. Relative `GEMINI_CLI_HOME` values resolve from the modeled session's native working directory. An empty value uses the OS home. An explicit `--home` selects its own user configuration.

Saved Gemini trust exposes the selected workspace rule and its source line. Unrelated entries are redacted from discovered aliases, imported context and diagnostics. Private-state files and their captured canonical aliases withhold raw previews. Rescan and re-export affected alias or imported-state reports created with 0.3.32 or 0.3.33 to apply these protections.

Claude shared-project permission grants and additionalDirectories entries remain conditional under unknown trust and ignored under explicit untrusted state. Local grants without explicit trusted state remain conditional because native Git/session checks can admit or withhold them. User/system grants and restrictive ask/deny entries have their own applicability. Permission masking checks exact and tool-wide coverage in deny → ask → allow order. Findings and shadowed entries retain every matching source at the highest overriding priority. EndConversation ask rules are ignored, and its deny rules depend on the uncaptured tool inventory.

`--system` includes Claude's fixed platform policy directory and its immediate, nonhidden `managed-settings.d/*.json` files, in alphabetical order after `managed-settings.json`. Results assume that the file-based managed tier is selected on the machine. `allowManagedPermissionRulesOnly` excludes ordinary allow/ask/deny lists and skill allowed-tools grants. `allowManagedHooksOnly` excludes ordinary hooks. `disableAllHooks` follows settings precedence, with managed hooks protected from ordinary-scope disabling. Ignored extensions retain a link to their controlling setting. Malformed managed JSON objects block effective contributions and produce a startup finding. Supported Boolean repairs and permission-list repairs follow the managed policy contract. Selection among remote, MDM, registry and embedding-host policies requires live-session evidence.

Reports write only when `--output` is supplied. Output uses a temporary sibling and atomic rename; invalid CLI input does not create partial files. The UI never writes user configuration. The default scan never executes a client, hook, MCP server or skill script.

JSON `schemaVersion: "1.0"` includes tool, repository, target, sessionDirectory, assumptions, sources, clients, findings and diff. A finding has `id`, `ruleId`, `severity`, optional `client`, `message`, `location: {path,line,column,key?,sourceId?}`, `related`, `why` and `suggestion`. Missing/invalid config is a finding, not a crashed scan.

`instructionDiff` is an additive array of exact paragraph groups with `content`, `clients` and `origins`. Each origin has a `client`, `location`, optional `endLine`, and a one-based `order` within that client's loaded paragraph sequence. CRLF normalizes to LF for matching, fenced code blocks remain intact, and wording and indentation remain significant. Membership is computed from proven loaded content before privacy redaction. Repeated occurrences keep separate origins. Conditional and ignored decisions remain available in the client explanations. An omitted `endLine` identifies transformed text whose origin links to the source contribution's start. Whole-source groups remain in `diff`, and terminal rendering supports earlier reports that omit `instructionDiff`.

Browser instruction coverage includes structured files imported as context. Each client cell groups every instruction contribution by loading status and links to its exact source occurrence. Select a group with multiple contributions to inspect their individual source lines and reasons. Configuration roles identify clients using the file as structured configuration. Differences only compares each source's complete sequence of instruction contributions. Overview and effective-text comparisons count unique source IDs across repeated segments. Coverage also works with earlier reports that omit `instructionDiff`.

Browser extension comparison exposes every active and conditional definition for each client. Status differences participate in its filter, and each definition opens its own resolved configuration and source origins. Complete extension names retain embedded separator characters.

Instruction decisions may include an additive one-based `column` alongside `line`. Gemini tree imports split a file into contiguous literal segments around imported content. Each segment retains its original starting position and import origin. Effective text includes Gemini's context and import delimiters. Repeated source rows identify separate contributions in loading order.

Captured private values are redacted from configuration payloads, source text, paths and diagnostic prose. Engine-generated client IDs, statuses, rule IDs, source IDs, trust input modes and version metadata retain their stable JSON representation. Exporters apply credential redaction again to caller-modified reports.

Captured multi-line values match LF, CRLF and mixed line endings. Paragraph comparison uses whole-contribution redaction context. A paragraph intersecting a private value spanning multiple paragraphs is displayed as `[REDACTED]` across its receiving group. Membership, source locations and loading order retain their generated metadata. v0.3.5 corrects this handling for reports generated by v0.3.4.

Sources may include an additive `preview` string containing the redacted source file. Internal account/session state and syntax-invalid files omit this preview. Parser recovery can discard environment values or duplicate definitions, so syntax-invalid sources retain their diagnostic locations and loading decisions without raw previews. After correcting their syntax, rescan to view a redacted preview. The inspector uses available previews for line-numbered source navigation. Snapshot reports retain source exploration and comparison while live target rescanning remains in the local UI.

Structured previews redact decoded values at their parser ranges, covering escaped JSON/TOML strings and YAML folded blocks and aliases. Private values use quoted placeholders and line padding to retain original line counts. Source byte counts, lines and columns refer to the original file. Internal value ranges and decoded values are excluded from reports. Private mapping settings use parsed key paths, so literal dotted keys and stored hook identifiers keep their own interpretation.

Comparison links capture selected client IDs in `clients`, paragraph filtering in `content`, full source coverage in `differences=all` and an expanded paragraph count in `paragraphs`. Reload, browser history, live refresh and offline report export restore these choices. A single selected client is retained. Unavailable client IDs are excluded, and a selection with no available clients falls back to the report’s defaults. Invalid filters and paragraph counts use their defaults.

The browser’s line comparison aligns two selected clients’ displayed redacted effective text. Its left and right line numbers index that text. CRLF is normalized, while indentation, repeated lines, empty text and final-newline differences retain their meaning. Inspect sources opens the corresponding client’s loading chain. Comparison links add `left` and `right` client IDs, `unchanged=show` for unchanged context and `lines` for expanded rows. Pair changes discard stale results. Calculations use a one-second budget and show complete replacements when alignment reaches it. The initial 200 rows can be expanded on demand. Older reports can use this view from their captured effective text.

Adjacent removal/addition blocks highlight changed words. Single-word replacements sharing at least half the longer word’s graphemes receive finer character highlights. Unicode grapheme segmentation keeps combining marks, skin-tone modifiers and joined emoji together. Highlighting preserves spaces, tabs, punctuation and the complete displayed text. Each render processes at most 16,000 previously unaligned UTF-16 code units, and each word or character alignment has a 200-edit limit. Larger or more complex blocks and browsers without Intl.Segmenter retain complete line-level highlighting. These highlights are regenerated from captured redacted text in standalone and re-exported reports.

A `finding` fragment parameter selects an existing finding ID in any view. Grouped findings accept each contributing client's original ID. Opening an issue, reloading and browser Back/Forward retain the selected details. Closing returns to the preceding inspection and restores its finding control when available. An unavailable ID clears the selection and displays a status message. Source inspection links back to the selected diagnosis through browser history.

The finding dialog provides Copy diagnosis and Export diagnosis report. Copied text includes the rule, severity, message, portable target, contributing client names, location, available redacted source line, reason, suggestion and related source locations. It reads the retained portable snapshot. Clipboard denial opens a selected text field for manual copying. The export action saves a complete portable report whose navigation metadata opens that diagnosis. Offline re-export retains the selected finding. Regenerate earlier standalone HTML to use the updated application.

Clipboard success appears in the active dialog's header and is announced through its status region. Headers keep the feedback and close control visible while scrolling long details. Closing or changing details clears previous feedback. Copying from the page uses the page status message. Keyboard hints use Command on Apple platforms and Ctrl on Windows and Linux, recalculated in the recipient browser when opening a portable report. Manual-copy instructions include phone text selection.

The browser's Export report action saves the most recent successful inspection. Opening the file restores its exported view, client, source occurrence, linked line and effective-text mode. Offline re-export saves the current location. A fragment supplied in the browser address selects that destination. Saved source paths use the portable report’s replacements. Configuration edits appear after Refresh scan. Exports during an in-flight or failed refresh keep the last displayed report, including its target, starting directory, trust and selected Codex profile.

Source links in the inspector include a one-based line number. Following a finding, setting, extension or comparison origin scrolls that line into view. Reload and browser history restore the line in local and portable reports. Fresh document loading reapplies the linked line after native scroll restoration, including reload after keyboard focus moves to source controls. Refresh scan retains the selected line in the local inspector. Opening a different source clears the previous line selection. The header keeps navigation and export accessible while reading long sources. Local target, trust and profile controls and scan errors stay in the same header. Source jumps account for its current height. The filename bar also stays visible, with source and explanation panels retained beside long code on wide desktop layouts. Long paths keep their complete text in source details and the filename tooltip. Selecting a new view opens its heading and filters. Browser Back/Forward restores the previous reading position. Source headings, search and filters stay above the independently scrolling list on desktop. Deep links, source jumps, reload, history and local refresh reveal the selected row within that list. Layout changes keep it visible, and source buttons expose their selected state to assistive technology.

Codex Skill discovery follows directory links in its documented user and project Skill roots. It reads regular `SKILL.md` files, skips hidden child directories and uses the pinned client’s six-level directory depth, 2,000-directory limit and 20,000-entry limit per root. User roots also obey `--max-user-files`. Sources found through another discovery path receive an unverified loading decision when Codex’s root inspection is incomplete. Project roots obey the smaller of their entry budget and `--max-entries`. Canonical aliases contribute one Skill definition, and `skills.config` paths resolve from their declaring configuration file. Source locations expose the logical installation path. Portable reports replace captured canonical file references with their known configuration aliases.

Repeated decisions for one physical source have separate rows in loading order. Selecting a row or an effective-text source origin inspects that specific decision's status, loaded bytes, reason and import provenance. Browser links add an optional one-based `occurrence` parameter for later decisions of the same path within the selected client. The selector survives reload, browser history and local refresh. Export uses the corresponding occurrence in the portable capture, including aliases that share a replaced path. A file-only link, an invalid selector or an unavailable occurrence selects the first decision for that path. Occurrence numbering follows the captured list, so rescanning after import edits can change the associated parent. Portable reports retain their captured list. Import origins link to their declaring file and line when that source exists in the report. The JSON decision records already carry this provenance.

Source search matches captured full and displayed paths, including an import origin’s path and line. Separate terms with spaces to require all of them, such as `shared beta.md:3`. Matching ignores case, surrounding whitespace and slash direction. In scope can hide ignored matches. Show all discovered reveals them and focuses the list. Clear search restores results and focuses the input. A result summary announces the visible and captured source counts.

Effective-text source origins and instruction coverage links clear the source search before opening their destination. Sidebar clients, overview client cards, instruction-chain links and the discovered-source overview also start with a clear source search. Browser Back/Forward clears a search that excludes the restored source. A matching query stays in place. Selecting rows in a filtered list and refreshing a local scan retain search text.

Opening a view focuses its heading. Following a source location focuses the filename heading, which exposes the loading status to assistive technology. Shift+Tab returns to the source list. The list has one Tab entry for the selected source or the first filtered result. Arrow keys move focus, Home/End reach the first/last row, and Enter selects it. Mobile navigation contains keyboard focus while open, provides an explicit close button and returns focus to the toggle on Escape. Scan scope and keyboard help close the menu before opening. The local target-search shortcut also closes the menu before focusing the file picker. Responsive layout changes restore a visible navigation focus.

Use rule IDs for CI integrations; prose is not a compatibility API. JSON keeps absolute paths for diagnosis. HTML replaces captured repository paths with `<repo>`, home paths with `~` and external agent configuration roots with `<codex-home>`, `<claude-home>` or `<copilot-home>`. Filesystem-verified aliases from absolute structured values and `--option=path` arguments share those replacements. Unknown paths in prose or shell snippets can remain.

Portable HTML replaces those paths and removes `pathMappings`. Source byte counts and line numbers describe the original files.
