Install Sightline

Download the v{{VERSION}} package. You’ll need Node.js 22 or later on macOS, Windows or Linux.

Download CLI package ↓

Runtime dependencies are bundled. After downloading the package, you can install offline with npm install -g --offline ./agent-sightline-{{VERSION}}.tgz, or install directly from the public package URL.

npm install -g https://github.com/iamzwxyy/agent-sightline/releases/download/v{{VERSION}}/agent-sightline-{{VERSION}}.tgz

Open the bundled sample in your browser. It includes intentional configuration problems and excludes personal configuration.

agent-sightline demo --ui

You can also open the sample with a single command.

npx --yes https://github.com/iamzwxyy/agent-sightline/releases/download/v{{VERSION}}/agent-sightline-{{VERSION}}.tgz demo --ui

The package is distributed through public GitHub Releases and website downloads. Public npm-registry publication is pending.

Your first scan

Open a terminal in any repository subdirectory and run the CLI. Sightline finds the nearest Git root and includes applicable ancestor configuration. It discovers documented configuration sources and reports deterministic problems.

Relative target paths resolve from your current directory. Use --repo to select an explicit inspection boundary and resolve targets from that directory.

agent-sightline

For the browser inspector, run the UI command. It opens a local page with an overview of your clients and actionable findings.

agent-sightline ui

Choose a target file in the top bar. Search by filename, path or fuzzy query, then use the arrow keys and Enter to select a result. You can also inspect a typed path. Press ⌘K on macOS or Ctrl+K on Windows and Linux to focus the target picker.

Follow an instruction through

Select a client from the sidebar. Sources appear in loading order. Choose a file to read its source preview, inspect its loading decision and see the exact byte contribution.

“All discovered” includes ignored and shadowed files, so you can find a configuration that exists on disk but doesn’t reach this client. Search the list with / and move between source buttons with the arrow keys.

Switch to Read effective text to read the exact accumulated instructions. Each source in the loading chain links back to its definition. Open Settings to search resolved values, inspect the winning definition and follow the layers it replaces.

You can get the same explanation in the terminal.

agent-sightline explain src/payments/refund.ts --client codex --trust trusted

The target’s directory models the starting directory of a fresh agent session. The trust selector changes the modeled assumptions. It doesn’t modify your client’s saved trust settings.

Inspect a Codex profile

When you launch Codex with --profile review, inspect the same profile in Sightline. It loads $CODEX_HOME/review.config.toml after user defaults and before project settings. Select a setting to follow its winning and replaced definitions.

agent-sightline explain src/payments/refund.ts --client codex --profile review --trust trusted

The local inspector’s Codex profile field selects the same file. Leave it empty and apply to return to base configuration. The choice survives reloads and appears in report snapshots. Profile files require user configuration, so --no-user excludes them.

Compare client perspectives

Open Compare clients to read the exact loaded instruction text side by side, followed by a source-by-client coverage matrix. Select the clients you use and turn on Differences only to focus on loading differences. Click any status to inspect the source and its reason for that client.

Extension comparison shows commands and definitions for MCP, skills, hooks and permissions. Select a definition to inspect it.

agent-sightline diff src/payments/refund.ts --clients codex,claude,copilot

Share what you found

Export report creates a standalone HTML snapshot. It includes the interactive source explorer, client comparison and findings. Open it in a browser or send it to a teammate.

agent-sightline report --format html --output report.html

The snapshot uses portable repository paths and redacts environment/header values and recognized secrets. Review prose and personal information before sharing a report.

Catch configuration errors in CI

Use repository-only discovery for a reproducible CI scan. Set the severity that should fail your build.

agent-sightline ci --no-user --fail-on warn --json

Exit code 0 means the inspection completed without reaching your threshold. Code 1 means findings reached the threshold. Code 2 identifies an input or inspection error. Rule IDs and JSON schema version 1.0 support scripted integrations.

Know the inspection scope

Codex 0.167.2 uses a pinned official source and schema. Claude Code 2.1.322 and Copilot CLI 1.0.109 use official documentation contracts with executable fixtures. Gemini, Cursor and OpenCode V2 have experimental adapters with partial scope.

Open Scan scope & rule versions in the inspector for official source links and each adapter’s limits. Command-line overrides, running-session toggles, installed plugins and remote managed policy may contribute additional configuration.

Discovery defaults to 50,000 repository entries and 4,000 matching files per user configuration root. Use --max-entries and --max-user-files to adjust these budgets. Incomplete discovery stays visible in the inspector and exported reports, including when findings are filtered.

Scans run locally, with no telemetry, model calls or uploads. The default scan reads your repository and documented user configuration locations. Add --no-user for repository-only discovery. External private trees are skipped.

By default, extension diagnostics check discovery and configuration. The explicit doctor --probe command starts local stdio MCP processes, initializes them and lists tools. Starting server code can have side effects. Hook commands and MCP tools are never invoked by a scan.
